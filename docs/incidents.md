## 2026-10-08 · 03 · 输出换行符随平台变化

**发生了什么**
工具在 Windows 上输出 CRLF、在 Linux 上输出 LF。同一份产物，两个平台两种字节，提交后制造无意义的 diff。

**为什么没被发现**
只有「在另一个平台上跑、并比对」才会暴露。而触发它的这个动作**不在正常使用路径上**——平时只用一个平台。

**最后怎么处理的**
**根治**：代码里强制 LF（`write_text(newline="\n")` + `sys.stdout.reconfigure(newline="\n")`）。
问题不再产生，因此**不加检查**，也不走门控判据。

**分类**：静默 · 逃逸概率低 · 逃逸代价中 · **根治 ✓**

## 2026-10-08 · 02 · README 示例输出块过期

**发生了什么**
加了 `treegen.sh` / `treegen.cmd` / `TREE.md` 之后，README 里的示例输出没跟着改，少了三个文件。

**为什么没被发现**
读 README 是为了**学会用**，不是为了**验证 README**。「比对示例与真实输出」是一个额外动作，没有任何人为了别的目的会去做。

**最后怎么处理的**
**根治 ✓**：README 的示例块改成**形状示意**——只描述输出长什么样（目录排在文件前、每层缩进 4 空格、根目录名在第一行），**不列任何具体文件**。因为它不引用具体事实，**所以不可能过期**。完整输出改由 `examples/sample.txt` 承载。

> ⚠️ **此决定已被事故 04 取代。** `examples/sample.txt` 本身也是会漂的副本，已删除；完整输出改指向 `TREE.md`。
> **推翻前面的决定时，要回到原处标注。** 否则读的人会看到两个互相矛盾的方案，而不知道哪个作数。

> **关键判断**：项目里原本有**两层副本**——
> `真实输出 → examples/sample.txt → README 示例块`
> README 那一层是**纯冗余**（内容完全被 `examples/sample.txt` 覆盖），所以直接消掉。
> **副本层数越少，漂移点越少。**

**分类**：静默 · 逃逸概率高 · 逃逸代价中 · **根治 ✓**

## 2026-10-09 · 06 · 检查的报错文本丢层级，说不清缺什么

> **发现方式：搭 pre-commit hook 时暴露。** 不是猜的——是它当场报了一条看不懂的错。

**发生了什么**
新加 `.githooks/pre-commit` 后，检查报：

```
缺少：.githooks/ pre-commit
```

**看起来是两个并列的条目**，完全看不出 `pre-commit` 在 `.githooks/` 里面。

**为什么没被发现**
差异是**直接 diff 两棵缩进树**得来的，然后 `sed 's/^> +//'` 把缩进**连同层级一起剥掉**了。
以前只测过单层目录的漂移，缩进浅，剥掉看不出来；`.githooks/` 是第一处两层嵌套。

**最后怎么处理的**
**根治**：比对前先把树**展开成完整路径列表**（`tree_to_paths`，用 awk 维护一个祖先栈），
diff 的对象从「树的行」变成「路径」。报告也从单行改成**每项一行**。

**分类**：静默 · 逃逸概率中 · 逃逸代价中 · **根治**

> **它属于 K5.3 说的那一类**：报错文本是检查**唯一的接口**，接口写得差，规则等于没有。
> 这条检查一直是对的（该红就红），**但它说不清自己在红什么**——那就是接口的问题，不是判据的问题。

> **顺带确认（不是事故）**：`TREE.md` 是 `-d 2` 的产物，**只覆盖前两层**——更深的文件不在检查范围内。
> **这是设计取舍，不是漂移**：检查的对象是「TREE.md 与 `-d 2` 的输出一致」，不是「TREE.md 覆盖了全部文件」。
> 已记入 `AGENTS.md` 与 `README.md`。**之所以在这里提一句，是因为读这条事故的人自然会问「那检查到底覆盖了多少」。**

## 2026-10-08 · 04 · `examples/sample.txt` 与 `TREE.md` 都会漂

**发生了什么**
`examples/sample.txt` 是真实输出的快照，`TREE.md` 是目录结构的快照。目录一变，两者都过期。

**为什么没被发现**
触发它的动作（跑一遍工具、再和快照比对）**不在正常使用路径上**。读文档的人是为了**学会用**，不是为了**验证文档**。

**最后怎么处理的**
分两步，因为两个副本的**性质不同**：

**1 · `examples/sample.txt` → 根治（删掉）**
它的内容已被 `TREE.md`（depth-2 输出）**完全覆盖**，是**纯冗余副本**。删掉它不丢任何内容，README 改指向 `TREE.md`。

**2 · `TREE.md` → 不能根治，加检查**
它必须提交，才能离线看、才能被 agent 当地图读——**副本消不掉**。三个量：

| 量 | 档位 | 理由 |
|---|---|---|
| 静默 / 响亮 | **静默** | 比对不在正常使用路径上 |
| 逃逸概率 | **高** | 每次增删文件都触发 |
| 逃逸代价 | **中** | 读者 / agent 按过期目录树找文件 |
| 等待成本 | **低** | 能自动修复，不需要人做判断 |

→ 期望损失 > 等待成本 → **该门控** ✓
→ 且**违反后能自动修复** → **纯 Sensor**，不放前馈位

**实施**：`scripts/check-tree.sh`（默认修复模式；`--check` 只检查不修改，给 CI 用）

**分类**：静默 · 逃逸概率高 · 逃逸代价中 · **根治（一半）+ 纯 Sensor（一半）**

> **这是本项目的第一条真约束。** 前面三条事故都靠根治解决，一条检查都没加。

## 2026-10-09 · 05 · 扫描器静默跳过无法读取的目录

> **发现方式：代码审查（未实际发生）。** 这是一条**潜在**事故，不是踩出来的。
> 记录它，是因为**不修的话它下一次就会真的发生**——而且不会有人知道。

**发生了什么**
`scan()` 里的 `walk()` 遇到 `PermissionError` / `FileNotFoundError` 时直接 `return`——**跳过那个目录，不记录、不报告、不影响退出码。**

**为什么没被发现**
产物看起来**完全正常**。目录本身还在（它在父层就被记下了），**丢的是它下面的内容**——而一个空的目录节点，和"这个目录本来就是空的"，在 `TREE.md` 里长得一模一样。

**最后怎么处理的**
**根治**：让跳过变成**可见的**。

1. `scan()` 返回 `(entries, skipped)`，`skipped` 记录 `(相对路径, 异常类名)`
2. `cli.py` 把 `skipped` 打到 **stderr**（不是 stdout——stdout 是数据通道）
3. **有跳过就返回非零退出码**——产物残缺时不能报"成功"
4. `check-tree.sh` 同步处理非零退出码，给出四段式报错

**分类**：静默 · 逃逸概率低 · 逃逸代价中 · **根治**

> **连带发现：循环验证。**
> `check-tree.sh` 比对的是「treegen 的实时输出」和「`TREE.md`（也是 treegen 生成的）」——**两边是同一个来源**。treegen 系统性漏东西时，两边一起漏，**检查永远绿**。
> **所以修法在上游**（让 treegen 不再静默漏），**不在下游**。
